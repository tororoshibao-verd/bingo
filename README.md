# BINGO

抽選する画面と、参加者が持つビンゴカード画面を連動させるブラウザゲーム。

抽選画面で番号を引くと、各カード画面の該当するマスが開く。カードがビンゴを申告すると、抽選画面が内容を確認して当選を確定し、抽選画面の当選者一覧に表示する。手元のカード画面は、自分のカードと最新の確定番号を中心としたシンプルな表示にする。

初版は、1台のパソコン・同じブラウザの同じプロファイル・同じサイト内で、複数のタブまたはウィンドウを開いて遊ぶ。データ共有には `localStorage` を使う。将来、別のブラウザや端末からも参加できるように、ゲームの処理とデータ共有の処理を分けて設計する。

作成日：2026年11月20日（日本時間）

最終更新：2026年11月20日（日本時間）。偶然の配置一致の許容、独立したランダム生成、名前の上限10文字、当選者一覧の抽選画面への集約、演出の後回しを反映。

現段階は企画・要件整理。このREADMEは、会話で決まった内容と実装時に満たす条件を整理したもので、機能の実装・動作確認が完了したことを示すものではない。

## 1. 作りたい体験

- 進行役は、抽選画面からカードを発行し、番号の抽選・ゲーム終了・リセットを操作できる。
- 参加者はカードに名前を登録し、自分のカードが自動で開いていく様子を見られる。
- ビンゴした人が出ると、全員が見る抽選画面の当選者一覧で、誰がビンゴしたか分かる。各カード画面には当選者一覧を表示しない。
- 再読み込みしても、自分のカードや抽選の進み具合が変わらない。
- 同時に複数のカードがビンゴしても、申告が消えず、同着として扱われる。
- 次の抽選とゲーム終了の前に、その時点までの結果を全参加カードについて確認する。未応答は当選なしと決めつけない。
- カードの発行枚数に固定の上限を設けない。以前検討した「最大5枚」は採用しない。ただし、ブラウザの保存容量・メモリなどの実際の制約は受ける。
- 初版はゲームを最後まで動かせることと、保存・同期・判定の検証を優先する。スタンプ・抽選アニメーション・効果音などの演出は、基本機能の完成後に考える。

## 2. ビンゴの基本ルール

75球式のビンゴを使う。

| 項目 | ルール |
| --- | --- |
| 抽選する番号 | 1〜75。各番号は1ゲームに1回だけ出る |
| カードの大きさ | 5行×5列、合計25マス |
| FREE | 中央の3行目・3列目。最初から開いている |
| カードの数字 | 24個。同じカードの中では重複しない |
| ビンゴ | 縦・横・斜めのいずれか1列、5マスが開くこと |
| 判定する列 | 縦5列・横5行・斜め2本、合計12本 |
| 当選の扱い | カードごとに最初のビンゴを記録する。複数列完成しても、同じカードを重複当選にしない |

各列の数字は、以下の範囲から重複なしでランダムに選ぶ。列内の位置もランダムにする。

| 左からの列 | 候補の数字 | 選ぶ個数 |
| --- | --- | --- |
| B | 1〜15 | 5個 |
| I | 16〜30 | 5個 |
| N | 31〜45 | 4個＋中央FREE |
| G | 46〜60 | 5個 |
| O | 61〜75 | 5個 |

別のカード同士で同じ数字を使うことは問題ない。正常なランダム生成の結果、偶然カード全体の配置が一致した場合も許容し、一致を検出して作り直す処理は設けない。

ただし、カードは毎回独立に生成する。各列の候補から重複なしで均等に選び、列内の位置もランダムにする。固定パターンの使い回し、既存カードの誤複製、同じ乱数列の意図しない再利用は実装上の不具合として扱う。FREEと列ごとの範囲は、ランダム生成でも必ず守る。

### 完全に同じ配置になる確率

上記のルールで、各列の位置を含めて独立・一様にランダム生成できていると仮定する。

- B・I・G・Oの各列：15個から5個を順番付きで選ぶため、`15 × 14 × 13 × 12 × 11 = 360,360` 通り。
- N列：15個から4個を順番付きで選ぶため、`15 × 14 × 13 × 12 = 32,760` 通り。
- カード全体：`360,360^4 × 32,760 = 552,446,474,061,128,648,601,600,000` 通り（約 `5.52 × 10^26` 通り）。

| 比較する状況 | 完全一致が起こる確率 |
| --- | --- |
| 独立に作った2枚が一致する | 約 `1.81 × 10^-27` |
| 1,000枚の中で、どれか2枚以上が一致する | 約 `9.04 × 10^-22`（近似） |

複数枚の場合の近似は、発行枚数を `n`、配置総数を `M` として `n(n−1) / (2M)` で計算。今回のように確率が極めて小さい枚数での近似値とする。

これは正常な独立・一様生成を前提にした理論値。保存済みカードの誤複製や、同じ乱数列の再利用などの実装不具合を含むものではない。また、別配置のカードが同時にビンゴすることは、完全一致とは別の事象として扱う。

## 3. 画面ごとの役割

### 抽選画面：進行と当選確定を担当する

| 機能 | 行うこと |
| --- | --- |
| ゲームの準備 | ゲームを識別する `gameId` を発行し、1〜75の番号が入った「プール」を用意する |
| カード発行 | 新しいカードを識別する `cardId` を発行し、そのカード画面を別タブで開けるようにする |
| 参加締切・ゲーム開始 | 準備中にカード発行と初回登録を受け付け、開始時に締め切る。開始後は新規発行・新規登録を受け付けず、登録済みカードの復元は可能にする |
| 抽選 | プールから1個をランダムに取り出し、プールには戻さない |
| 抽選結果の共有 | 最新の番号と、それまでに出た番号の順序付き履歴を保存する |
| 進行状況の表示 | 最新の番号、抽選履歴、抽選回数、残りの球数を表示する |
| ビンゴ申告の確認 | 各カードの申告を読み、保存されたカードと抽選履歴を照合する |
| 各抽選後の確認 | 全参加カードが今回の抽選まで確認したか調べ、未応答分も照合してから次へ進む |
| 当選確定 | 確認できた申告を当選者一覧に反映する |
| 当選結果の保存・表示 | 確定した当選者一覧を保存し、抽選画面に表示する。各カードへは自分の確定状態を確認できるようにするが、手元に他者の当選者一覧は表示しない |
| ゲーム終了 | 新しい抽選を止め、最終確認中に移る。最後の抽選まで全カードを確認してから終了を確定する |
| リセット | 旧ゲームの情報を削除し、カードID・名前も含めて最初からやり直す。新しい `gameId` のゲームを準備する |

進行役の操作権を持つ抽選画面は、1ゲームにつき同時に1つだけとする。二重に開いても、両方から抽選・終了・リセットを実行できないようにする。操作権を持つ画面を閉じた後の再取得にも対応する。

カード画面には抽選・終了・リセットの操作を置かない。初版はログイン認証ではなく、画面の役割と進行役の排他制御で操作範囲を分ける。

ビンゴが出ても、自動でゲームを終了させない。進行役が終了するまで、ほかのカードも続けて遊べる。

### カード画面：自分のカードと申告を担当する

| 機能 | 行うこと |
| --- | --- |
| 新規カードの作成 | 初回発行時だけ、列ごとの番号範囲に従ってランダムにカードを作る |
| 名前の登録 | 初回登録時に最大10文字の表示名を入力できる。未入力・空白のみの場合はカードIDを表示名として扱う。登録確定後の名前変更はできない |
| カードの復元 | 同じカードの再表示・再読み込みでは、保存済みの数字と名前を使う |
| 抽選結果の受信 | 保存された抽選履歴を読み、自分のカードの数字と照合する |
| マスを開ける | 出た番号にチェックマークなどを表示する。FREEは最初から開ける |
| ビンゴ判定 | 数字を照合した後、12本の列に完成したものがあるか確認する |
| ビンゴ申告 | 初めてそろった抽選回数を、自分のカード専用の保存先に記録する |
| 各抽選の確認報告 | ビンゴの有無にかかわらず、何回目まで確認したかと判定結果を、自分専用の保存先へ一緒に記録する |
| 最新番号の表示 | 抽選画面で確定した最新の番号を表示する。手元には他者の当選者一覧・通知を置かない |
| 終了・旧ゲームの表示 | ゲーム終了やリセットを認識し、進行中の新しいゲームと混同しないようにする |

同じカードのURLを再度開いた場合は、同じカードとして扱う。別のカードが欲しい場合は、抽選画面から新規発行する。

名前が同じでもカードIDが違えば別カードとして扱い、一覧では必要に応じてカード番号などを添えて区別する。

名前の10文字制限はユーザーが入力する表示名に適用し、未入力時の代替表示となるカードIDは省略・切り詰めずに識別できるようにする。11文字以上の名前は登録確定できないようにし、入力者に制限を伝える。

参加は締切方式とする。発行したタブを開いただけでなく、開始前に初回登録まで確定したカードが参加対象。未入力の名前はカードIDで代替するため、名前の入力自体は必須ではない。

ゲーム開始時に参加カードIDとカード配置を確定し、以降の確認対象にする。未登録の発行枠や開始後の新規登録を確認対象へ混ぜない。開始後はカード配置を変更できない。

### 初版の表示範囲

| 画面 | 表示するもの |
| --- | --- |
| 抽選画面 | 抽選番号、履歴、残りの球数、進行操作、確認状況、確定した当選者一覧（表示名／未入力ならカードID、同着が分かる順序） |
| カード画面 | 自分のビンゴカード、マスのチェック、最新の確定番号。登録・識別・終了・リセット・エラーなどに必要な補助表示は行う |

当選者一覧と他者の当選通知は抽選画面に集約する。リーチ表示は設けない。

### 基本機能完成後に考える演出

- ビンゴ時に、大きな「BINGO」のスタンプが勢いよく押される演出。
- 抽選時に、デジタルモニター上で数字がランダムに切り替わり、最後に今回の番号で止まる演出。
- 効果音、演出時間、細かな動き・見せ方。

上記は将来の演出アイデアとして保持する。初版の完成条件には含めず、演出なしでも全機能の操作・検証ができるようにする。追加する際は、仮の演出数字を履歴やカードに反映せず、確定番号だけを共有する。また、演出中の連打による重複実行を防ぐ。

## 4. データが流れる順番

### 番号を引いたとき

1. 抽選画面が、残っているプールから番号を1個選ぶ。
2. その番号をプールから除き、抽選履歴の末尾に追加して保存する。
3. 各カード画面が保存内容の変更を受け取り、抽選履歴を読み直す。
4. 自分のカードの該当マスを開け、ビンゴになったか判定する。
5. 各カード画面が、確認した抽選回数とビンゴ判定結果を一緒に保存する。
6. 抽選画面が報告を確認し、当選情報と確認状況を更新する。

共有するのは最新の1個だけではなく、抽選履歴全体。カード画面を閉じていた場合や変更通知を受け取れなかった場合も、履歴から現在の状態に追いつけるようにする。

### ビンゴになったとき

1. カード画面が「このゲームの、このカードが、第何回の抽選で初めてビンゴしたか」を保存する。
2. 抽選画面が申告を読み、対象のゲーム・カード・抽選履歴が正しいか確認する。
3. 抽選画面は、履歴のどの時点で初めてビンゴしたかを照合して、当選者一覧を更新する。
4. 抽選画面が当選者一覧を表示する。各カード画面が必要に応じて自分の確定状態を読み取れるようにする。

抽選画面が各タブへ個別に直接送信するのではなく、共通の確定結果を更新し、必要な画面がそれを読む。当選者一覧を各カード画面に描画する必要はない。

カード自身の判定と、抽選画面による当選確定はデータ上で区別する。カード側の申告だけで当選者一覧へ載せない。手元へのスタンプなどの演出は後付けとし、他者の当選表示は行わない。

### 次の抽選・ゲーム終了の前の共通確認

1. 次の抽選を始める前に、現在の抽選回数を対象に確認する。終了ボタンの場合は、新しい抽選を止めて「最終確認中」に移り、最後の抽選回数を確認対象として固定する。
2. 抽選画面が、ゲーム開始時に確定した全参加カードの確認報告を読む。
3. 対象の抽選回数までの有効な報告があるカードは、判定内容を照合して当選者一覧へ反映する。
4. 報告がない・古いカードは「未応答」として表示し、一定時間、今回の確認報告を待つ。
5. 待っても返答しないカードは、保存済みのカード配置と抽選履歴を使って、抽選画面が代わりに判定する。
6. 全カードについて結果の確認と保存が完了したら、次の抽選を許可する、またはゲーム終了を確定する。

例えば第20回まで抽選済みなら、「第19回まで確認済み」という報告では確認完了にならない。同じゲーム・カードの第20回までの報告が必要。未来の抽選回数や別ゲームの報告も受け付けない。

ビンゴしたカードも、その後の確認報告の対象に含める。最初にビンゴした回数は保持し、当選を追加登録しない。

### 未応答への対応と表示

- 閉じられたタブや処理が遅れているタブからの返答を、無期限に待ち続けない。
- 「カードからの確認済み」「進行役による代替照合済み」「未確認」を区別して記録・表示する。代替照合を、カードから実際に返答があったことにはしない。
- 代替照合はゲーム上の結果を確認するもの。カード画面に描画されたことや、参加者本人が見たことの確認までは意味しない。
- 保存済みカードが欠損・破損していて代替照合できない場合は、確認できない理由を表示し、勝手に当選なしとして次へ進めない。
- 代替照合後にカードの報告が遅れて届いても、同じ結果を重複確定しない。
- 確認中に次の抽選や終了操作が重なっても、処理を二重実行しない。終了が求められている場合は、確認完了後に次の抽選へ進めない。
- 報告の保存では、確認済み回数とビンゴ判定結果を同じレコードに含める。「確認済み」だけが先に保存され、判定結果が未反映になる状態を作らない。
- 最新の報告を保存し、各回の結果はカード配置と抽選履歴から再現する。毎回すべての過去報告を追加して蓄積する必要はない。

待機時間は調整可能な設定にし、通常操作・未応答・多数カードの検証を通じて決める。画面には確認済み件数と未確認件数を表示する。全参加者の確認には枚数に応じた処理が必要になるため、意味のない保存・全件再走査を細かい間隔で繰り返す実装は避ける。

## 5. 保存する情報と更新する担当

| 情報 | 主な内容 | 更新担当 |
| --- | --- | --- |
| 現在のゲーム | 現在の `gameId` | 操作権を持つ抽選画面 |
| ゲームの進行情報 | `gameId`、ゲーム状態、参加カードID、残りのプール、順序付き抽選履歴、確定した当選者一覧、抽選回ごとの確認状況 | 操作権を持つ抽選画面 |
| カード情報 | `gameId`、`cardId`、表示名、25マスの配置（中央はFREE） | そのカード画面 |
| 確認報告（ビンゴ申告を含む） | `gameId`、`cardId`、確認済み抽選回数、ビンゴの有無、初めてビンゴになった抽選回数 | そのカード画面 |

### 保存時の原則

- カード情報と確認報告は、ゲームID・カードIDごとに保存先を分ける。
- 複数カードが共通のカード一覧や申告一覧を読み書きして、丸ごと上書きする方式にしない。
- 確定した当選者一覧を書き換えるのは、操作権を持つ抽選画面だけにする。
- 残りのプールと抽選履歴など、同時に整合している必要のある進行情報は、一まとまりとして保存する。
- カードの開閉状態は、カードの配置と抽選履歴から再現する。別の状態を二重管理して食い違わせない。
- ゲームID・カードIDを保存先に含め、別のゲームやカードと混ざらないようにする。
- アプリ固有の接頭辞を保存キーに付け、リセット時にほかのアプリの保存データを消さない。`localStorage.clear()` で保存領域全体を消す実装にはしない。

### 読み込み・通知の原則

- 初回表示・再読み込み・抽選画面の復帰時は、保存済みの状態を読み直す。変更通知を待つだけにしない。
- 他タブからの変更は `storage` イベントで検知し、必要な保存情報を読み直す。
- 自分で保存した画面では、その画面の表示も自分で更新する。自分の変更に対する `storage` イベントには依存しない。
- 抽選画面の再表示時には、すでに保存されている未処理のビンゴ申告も確認する。
- 未保存・壊れた保存データ・保存容量不足を検知し、利用者に状況を表示する。保存に失敗した処理を成功扱いにしない。

## 6. 同時操作と当選順のルール

### 同時申告でも情報を失わない

カードAとBが同時にビンゴした場合、AはA専用、BはB専用の保存先へ申告する。抽選画面は両方を読み、当選者一覧へ反映する。

同じ申告を複数回受け取っても、ゲームIDとカードIDの組み合わせで重複を除き、同じカードを二重登録しない。同じカードを複数タブで開いた場合も同様。

### 通知が届いた順番を順位にしない

- 当選順は「初めてビンゴになった抽選回数」で決める。
- 同じ抽選回でビンゴになったカードは同着とする。
- 遅れて届いた申告も、抽選履歴で確認できた本来の抽選回で扱う。後から一覧の表示順が更新される場合がある。
- 表示名・申告された回数だけを信用せず、抽選画面が保存されたカードと履歴を照合する。

### 古い画面からの更新を混ぜない

終了・リセット・進行役の交代後は、古い操作権や古いゲームIDで進行情報を書き換えられないようにする。

ゲーム状態は「準備中 → 進行中 → 最終確認中 → 終了」とする。進行中は各抽選の処理中・確認待ちを区別し、その間の重複操作を防ぐ。演出を後から導入した場合は演出中も同様に扱う。終了後もカードの読み取り・表示は可能だが、進行情報や確定結果を変更させない。

## 7. ゲーム終了とリセット

| 操作・状態 | 必要な動き |
| --- | --- |
| 進行役による終了 | 新しい抽選を止めて最終確認中にし、最後の抽選までの全カード照合後に終了を確定する。カード・抽選履歴・確定結果は表示できるようにする |
| プールが空になる | 76回目の抽選を実行させず、すべて抽選済みであることを表示する。最終回の確認工程も省かない |
| リセット | 旧ゲームのプール・履歴・カード配置・カードID・登録名・申告・当選者一覧を削除し、新しいゲームIDで初期状態を作る |
| 古いカードが開いたまま | 旧カードの数字・ID・名前・当選表示を無効化し、リセットされたことを表示する。自動で新カードを生成・登録せず、新規発行からやり直す |
| 過去ゲームのデータ | アーカイブしない。リセット時に都度削除する。単なるゲーム終了では、リセットされるまで結果を表示できるようにする |

旧カードのURLを再度開いても、削除したカードIDや名前を復活させない。古い画面から遅れて保存しようとする処理も、ゲームIDを確認して拒否する。削除対象はこのアプリの旧ゲームに関するデータだけとし、ほかのアプリの保存内容は残す。

終了ボタンを押した後、最終確認中は最後の抽選までの報告を受け付ける。返答しないカードも代替照合してから終了を確定するため、終了確定後に届いた同じ内容の報告で当選者一覧を変更する必要はない。リセット後の旧ゲームへの報告は受け付けない。

## 8. 初版の構造と将来の拡張

ゲームは学習用の3アプリとは別に、この `bingo` フォルダで作る。CSS・JavaScriptはHTMLと同じ階層に直接置かず、それぞれ専用フォルダにまとめる。

| 分けるもの | 責任 | 将来へのつながり |
| --- | --- | --- |
| ゲームの処理 | プールの作成、抽選、カード生成、ビンゴ判定、申告の検証 | localStorageやHTMLに直接依存しない形にする |
| 画面の処理 | ボタン操作、カード・番号・当選者の表示 | 抽選画面とカード画面で役割を分ける |
| データ共有の処理 | 保存、読み込み、変更通知 | 初版はlocalStorage。将来はネット上のデータ共有へ置き換える |

カードの報告・申告と進行役の確定は、別の役割として残す。通常はカード自身が各回の判定結果を返し、進行役が確認する。未応答分に限って、進行役の代替照合を行う。カードが少ないときだけ報告を省略する方式へ簡略化せず、枚数が増えても使える流れを採用する。

### 初版でできる範囲

- 同じパソコン・同じブラウザの同じプロファイルで、同一オリジンから開く複数画面の連動。
- オリジンとは、URLのプロトコル・ホスト名・ポート番号の組み合わせ。ローカル検証では同じ開発サーバーから両方の画面を開く。
- GitHub Pagesに公開する場合は、抽選画面とカード画面を同じサイトとして公開する。

### 将来追加する範囲

- 別のブラウザ・別の端末・離れた場所からの参加。
- ネット上の共有先への保存・購読、通信の遅延や失敗への対応。
- 必要に応じた進行役の認証、サーバー側での当選検証。

GitHub Pagesで公開するだけでは、別ブラウザ・別端末のlocalStorageは共有されない。データ共有部分を分けておくことで変更範囲を整理するが、ネット対応が単純な保存先の交換だけで完了するとは想定しない。

## 9. 検証したいこと

通常操作に加え、複数画面の同時操作・再読み込み・終了やリセットの境界を確認する。

| 検証ケース | 期待する結果 |
| --- | --- |
| 75回抽選する | 1〜75が各1回だけ出て、残りのプールが空になる |
| 抽選ボタンを素早く連打する | 同じ番号が再度出たり、履歴とプールが食い違ったりしない |
| カードを繰り返し生成する | 各列の数字範囲・重複なし・中央FREEを満たす |
| 縦5・横5・斜め2本をそれぞれ完成させる | どの列も正しくビンゴになる。4マスだけでは確定しない |
| FREEを通る列を完成させる | FREEを開いた1マスとして判定する |
| 複数カードをほぼ同時に発行・登録する | カードIDが衝突せず、他カードの数字や名前が消えない |
| ゲーム開始後に新規発行・登録しようとする | 締切済みとして拒否し、登録済みカードの復元は許可する |
| 名前を未入力・空白のみで登録する | カードIDが表示され、登録後の名前変更はできない |
| 名前を10文字・11文字で入力する | 10文字は登録でき、11文字以上は理由を表示して登録を止める |
| ランダム生成処理を確認する | 各列で候補を均等に選び、既存カードや固定配列の意図しない使い回しがない |
| 別IDのカードに同じ配置を与えて検証する | 偶然の一致を禁止する処理で拒否せず、カードIDごとに判定・当選確定できる |
| 同じ抽選で複数カードがビンゴする | すべての申告が残り、全員が同着として確定する |
| 同じカードの申告が複数回届く | 当選者一覧には1件だけ登録される |
| 代替照合後、数回遅れてカードの報告が届く | 照合済みの結果と整合し、当選者が重複したり確認済み回数が後退したりしない |
| 前回分までしか確認していない報告が届く | 今回の確認完了に数えず、今回分の報告または代替照合を待つ |
| ビンゴしていないカードが確認報告を返す | 確認完了として数えられ、ビンゴしたカードだけを待つ実装にならない |
| カードのタブを閉じたまま次へ進もうとする | 未応答を表示し、待機後に保存済みカードで代替照合してから進む |
| 次の抽選・終了の確認処理中に連打する | 確認や抽選が重複せず、終了要求後に次の番号を引かない |
| 最後の抽選直後に終了ボタンを押す | 最終確認中に届いた報告と未応答分の代替照合を処理してから終了する |
| 代替照合に必要なカード情報が欠けている | 未確認の理由を表示し、勝手に次の抽選や終了確定へ進まない |
| カードを再読み込みする | 数字と名前が変わらず、抽選済みのマスが復元される |
| 同じカードを複数タブで開く | 別カードとして増殖せず、同じカードIDを維持する |
| カードを閉じてから再度開く | 保存された履歴から現在の状態へ追いつく |
| 抽選画面を再読み込みする | プール・履歴・当選者を復元し、未処理の申告も確認する |
| 抽選画面を二重に開く | 同時に操作権を持つ画面は1つだけになる |
| 操作権を持つ抽選画面を閉じる | 別の抽選画面から操作権を再取得でき、二重更新にならない |
| 古いカードを開いたままリセットする | 古いID・名前・カード・申告を無効化し、新しいゲームへ混ぜない |
| リセット後に保存領域と旧カードURLを確認する | 旧ゲームのデータが削除され、URLから復活せず、ほかのアプリのデータは残る |
| 当選が確定する | 抽選画面だけに当選者一覧が表示され、カード画面には他者の当選者一覧・通知が出ない |
| 演出なしで一連のゲームを行う | 発行・抽選・同期・当選確定・終了・リセットまで完了できる |
| 保存データがない・壊れている | 無言で停止せず、状況を表示して扱える |
| 保存に失敗する | 成功したように表示せず、保存済みの進行状態を壊さない |
| 多数のカードを発行する | 固定の枚数制限がなく、資源不足時は状況を伝えられる |

同時操作のテストには、タイミングを意図的に重ねた検証を含める。たまたま順番に操作して成功しただけで、競合への対応ができたとは判定しない。

## 10. 決定事項と、残っている相談

### 決定済み

| 論点 | 決定内容 |
| --- | --- |
| ゲーム途中の新規参加 | 締切方式。ゲーム開始後は新規発行・新規登録を受け付けない |
| 名前未入力の扱い | カードIDを表示する |
| 名前の文字数 | 入力する表示名は最大10文字 |
| 登録名の変更 | 初回登録の確定後は変更不可 |
| 完全に同じ配置のカード | 正常な独立・均等のランダム生成による偶然の一致は許容し、配置の重複排除処理は入れない。実装ミスによる一致は修正対象 |
| リセット時のカード | 数字・カードID・名前をすべてリセットし、新規発行からやり直す |
| 過去ゲームの保持 | 保持しない。リセット時に都度削除する |
| 当選者一覧 | 抽選画面だけに表示する。各カード画面には表示しない |
| 手元の表示 | 自分のカードと最新の確定番号を中心にする |
| ビンゴ演出 | 大きなスタンプが勢いよく押される案を保持し、初版完成後に検討する |
| リーチ表示 | なし |
| 抽選演出 | デジタルモニターで数字が切り替わる案を保持し、初版完成後に検討する |
| 次の抽選の前の確認 | 全カードの今回分の結果を確認し、当選情報を反映してから次へ進む |
| 終了時の最終確認 | 最後の抽選まで全カードを確認してから終了を確定する |
| 未応答カード | 一定時間待った後、保存済みカードと履歴を使って進行役が代替照合する |

### 実装・検証中に調整する項目と、後回しにする項目

主要なゲーム要件は決定済み。以下の細部を先に作り込むことを、初版の完成条件にはしない。

| 論点 | 初版案・相談内容 |
| --- | --- |
| 確認待ちの時間 | 未応答分の代替照合へ移るまでの時間を、実際の検証で調整する |
| 当選者一覧の細かなデザイン | 初版は抽選画面で名前／カードIDと当選順・同着が分かればよい |
| スタンプ・抽選アニメーション・効果音 | 基本機能の完成後に改めて検討する |
